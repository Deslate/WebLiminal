# v1.33：让脚步波传播到第一人称可见区域

基于 `8893209`，保留 v1.31 池底修复。开始时只有用户的 BRIEF.md 与 .flops 未提交；本轮不包含这两项，不 push。

## 判断与实现

v1.32 的“更宽的弓浪 + 40° 俯视 + 14mm”没有达到用户要求。它主要展示身体附近的局部隆起，不能充分展示向外传播的脚步波。

代码核查发现另一项实际问题：原来的脚步压力由背景 PDE 接收，也受到背景时间倍率 0.28 的影响；人以 0.8m/s 前进，脚步波却在慢时钟里传播。隔离一次接触、经过两秒，旧版能量加权传播半径只有 0.87m。它难以跑到身体前方的可见区域。

现在，来自碰撞处理后真实步程的脚步事件进入已有的有限水深色散身体求解器，使用真实时间。每次接触施加 0.36 秒平滑加载/卸载的高斯压力，半径 0.60m，等效平衡高度强度为事件 amplitude×20（默认 0.24m）。这是**有效软压力的观感标定，不是脚掌真实尺寸，也不是经过实验标定的人体流固耦合**。没有设置圆环、V 形图案、传播半径或波臂角度；波形由受迫波方程演化得到，零波数清零，不注入净水量。停止接触后只关闭源，已经产生的高度/速度继续传播。

共享高度仍供真实水面求交、反射、折射和光子传输使用，未加法线特效或焦散层。源在下一次允许的脚步事件（至少 0.4 秒）之前已经结束，因此只需保留一个正在加载的接触；旧波保留在状态中。没有增加 FFT 尺寸或 pass 数。水面求交高度包围范围从 0.16 扩为 0.28m，以容纳实际更强的走动波，并非钳制波高。

默认视线改为向下 18.3°、24mm；背景波幅参数 0.052→0.018，时间倍率仍为 0.28。背景更安静，行走与静止更容易区分。持续身体压力的 0.36/0.25m 两个半径和增益 0.6 没变。

关于用户线索：相同眼睛位置、同一个水面点的入射角不会因转动相机改变；俯视改变的是画面选中的水面区域及其像素占比。v1.32 选择了更近、透明成分更多的水，也稀释了构图。67mm 高度本身不能证明肉眼不可见；传播位置、坡度、倒影内容和背景起伏更关键。因此没有改变菲涅耳反射率，而是调整真实受力、传播时钟、背景与构图。

## 隔离数据与强度代价

`contact-audit/single-contact.json`：平底无障碍控制域，关闭背景，t=1 秒注入一次默认脚步。下表 t=3 表示注入后两秒；“远处”是距接触点 1–4m 环带。

| 指标 | 旧脚步模型 | 最终模型 |
|---|---:|---:|
| 能量加权传播半径 | 0.871m | 2.707m |
| 远处高度 RMS | 0.103mm | 12.950mm |
| 远处法线角 RMS | 0.0418° | 1.6860° |
| 单次波全域绝对峰值（该时刻） | 1.500mm | 21.832mm |

这不只是时钟修复，还包括压力范围、持续时间与强度重新标定；不能把表中收益全部归于时间倍率。中间较小压力候选虽传播更快，但看起来仍弱，未采用。

使用真实步程、0.018 背景、同一路径，15 秒内每半秒测量一次组合高度绝对峰值：慢走 **84.43→143.81mm**，快走 **143.78→230.40mm**。这不是孤立弓浪高度，也不是连续时间最大值保证。快走扰动确实更强，属于本轮代价；它没有经过精确非线性破浪验证。停止后的尾波会继续存在，不能要求脚步一停画面立刻归零。

单次接触 t=4 秒的 30/60Hz 高度差：最大 0.00497mm、RMS 0.00144mm。无源平水初态保持为零。行走检测原有“转动/受阻/干地不产生脚步”测试保留。

## 物理近似与验证边界

脚步现在与身体共享谱求解器，也继承其**内部墙体边界不完整**的近似：背景 PDE 仍认识池壁，谱身体/脚步波没有实现内部障碍反射。旧脚步 PDE 在这方面更严格。没有把这个变化称为完整物理升级。强快走、狭窄通道、墙边反复转弯不属于已完成的严格流体验证。

npm test（16/16）、npm run build 通过。单独运行实时性能；额外验证相机历史独立性、共享水面/光照时钟及 30/60Hz 停步细化，结果见末尾与 `motion/`。

## 最终性能与回归结果

Apple M3 Max、Chrome headless / WebGPU Metal，固定内部 1280×832；录像和其他 GPU 测试均已结束后单独执行。没有降低光子数量、曝光或像素尺寸。默认第一人称三种模式为 **60.37–61.08fps**，最低一秒 **59.83fps**，最差 p95 **18.4ms**，首帧 **429ms**；另外明暗两处六种模式 **60.38–61.11fps**。数据见 `performance-default/performance.json` 与 `performance/performance.json`。没有用这组数宣称相对上一轮的严格性能提升，因为没有在此环境重测旧版。

六机位各 61 个连续相位、相机历史独立性、光学审计、30/60Hz 停步后一秒细化通过（`motion/synchrony.json`）。压力控制实验无 GPU 错误。
