# Tab 播放／暂停改键

只改变触发键与 UI 文案，沿用原有停止 RAF/GPU 提交、保留帧缓冲、恢复首帧使用原时钟的逻辑。

运行文件：`src/main.js`（Tab + preventDefault + 禁止自动重复切换）、`src/audio.js`（暂停提示）、`index.html`（操作与无障碍提示）。`scripts/verify-v135.mjs` 更新为 Tab 回归，检查 ESC 在两种状态均无效、焦点不变、默认行为被阻止、长按不反复切换、暂停无 GPU 提交、恢复精确相同、暂停 resize 保留画面与快速切换。

实测证据：`/Users/steven/Projects/workroom-v1.49-evidence/tab-final2/measurements.json`。暂停约 17 秒，GPU queue.submit 增量 **0**；时间和画面不变；`paused.png` 与 `resume-0.png` PNG 逐字节一致（因此逐像素一致），恢复时钟均 14.10870000000296 秒。恢复后 1280×832：33.85→34.81fps，p95 31.7→30.4ms，没有下降。

整机 GPU 活跃 99.1%，暂停 48.9%，关闭测试页后 48.0%。背景应用仍占 GPU，因此不能宣称整机接近 0%；本页面没有继续提交工作，暂停水平与关闭页面接近。本轮提供精确首帧与提交计数作为主要验收证据。

早期测试受到另一孤立执行者及项目页面占 GPU 干扰；另两轮在历史 resize 测试的错误画布宽度断言处超时（552 与实际外层画布 1100 不符），暂停/恢复断言已通过，但未作为最终完整通过结果。修正测试断言并固定内部尺寸后，最终全套断言通过。生产暂停逻辑未为这些测试改动。
