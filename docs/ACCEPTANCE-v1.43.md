## 消融与收敛：哪些解释得到支持

| 实验 | 结果 | 支持的判断 |
|---|---|---|
| 关闭主墙面釉面反射 | 主要亮斑仍在 | 不是釉面GGX方向不足造成的主要现象 |
| 关闭间接水光传播增量 | 主要亮斑仍在 | 不是粗漫反射探针的主要痕迹 |
| 关闭实时水光照度 | 大片亮斑消失 | 来自水面输运的直接光 |
| 分开关闭太阳/天光水光 | 关太阳后主要斑消失；关天光后仍在 | 主路为太阳→水面反射→墙面 |
| 太阳入射384²→768² | 同刻ROI照度RMSE/均值约1.11%；逐帧变化18.163%→18.152% | 全域加光子不能解决主要形态/运动 |
| 单独把右墙接收域648×147→1296×293 | 保持实时重建的物理范围；同世界坐标RMSE/均值0.567%，相关系数0.999985 | 4cm接收格不是这些大斑块的主要尺度来源 |
| 共享水面改为平面 | 内部聚焦消失 | 主要结构由当前波面的法线/曲率产生 |

接收域加密实验**只用 liveField 作结论**；未用该实验的缓存照明截图论证最终观感。加密、禁用分支、平面水都没有合入。太阳入射数对照和接收域对照是两种不同实验，不混为一谈。

原始证据：`ablation.png`、`source-ablation.png`、各同名子目录、`initial-grid-convergence.json`、`receiver-convergence.json`。接收域加密仍使用原物理滤波范围，因此该实验不等于证明原重建核没有偏差。

## 我的物理判断

水面会像随时间变化的曲面反射镜，将太阳投到墙上。接收位置附近光线汇聚时照度可以很高，相邻位置也可以很暗；有限天窗与建筑遮挡会限定照明区域。不能因为它有强对比、会动，就把它抹成均匀的光。判断应依据实际反射光路、光源角宽和采样收敛，而不是预先指定纹样。镜面反射与Fresnel依据：[PBRT](https://www.pbr-book.org/4ed/Reflection_Models/Specular_Reflection_and_Transmission)。

但旧实时水光把太阳当成**单方向、零角宽光源**，缓存光子却已使用0.00465rad角半径。真实太阳从地球看约半度宽（[NASA](https://eclipse2017.nasa.gov/exploring-angular-diameter)）。这是一处可以明确纠正的光源模型不一致。

**该不一致不是此次强明暗的主要成因。** 有限圆盘高采样参考仍保留大部分斑块。对于当前这张水面，主要聚焦是光路计算的结果；但背景水仍有之前报告过的浅水色散、短波耗散和长波补能问题，所以不能进一步推导“这就是现实静水应该有的样子”。原世界空间重建仍有有限核偏差，64方向参考只是角度收敛参考，并非离线真值。

## 正式修改

仅改 `water-caustics.wgsl` 的太阳积分与光通量记录精度，以及 `renderer.js` 的光包统计。

1. 太阳角半径沿用缓存的0.00465rad。四个对称圆盘节点匹配一、二阶矩；每个水面点追踪一对相反方向，相邻点使用另一对方向。共294912个太阳入射样本/帧（原147456），每条仍实际计算水面、遮挡、Fresnel、反射/折射及接收位置。功率除以2，保持总能量。
2. 原24位小数的整数光通量记录，在拆分很多弱反射光包时会向下截断能量。提高到30位小数；不增加缓冲大小。64方向实验若沿用原精度，ROI均值会错误地降至约0.1934；修正精度后为0.21326，说明不能把量化损失误认成有限光源的柔化效果。
3. 不改材质、水波/脚步、曝光、接收格、原重建核、反射滤波或帧历史。没有新增效果层、贴图或预设光纹。对称方向固定在光源空间，不按帧随机变化。

| 固定ROI，6–8s | 改前 | 改后 |
|---|---:|---:|
| t=6s，对64方向参考的RMSE/参考均值 | 1.560% | 0.486% |
| t=6s，空间标准差/均值 | 0.90818 | 0.90146 |
| t=6s，最大照度（引擎线性单位） | 1.46985 | 1.45666 |
| 序列平均照度 | 0.213895 | 0.214264 |
| 相邻1/30s帧差RMS/序列平均照度 | 18.163% | 17.588% |
| >8Hz时间功率占比（Hann窗） | 0.249% | 0.216% |

逐帧变化只降低 **3.16%**，不是把跳动“消除了”。线性平均照度增加0.17%，不是整体提亮方案。最初四条射线/点的候选没有作为最终方案；最终相反方向配对只用两条。

整数范围：8s站定样本的最大累加值12620954，为uint32上限的0.294%。另用1.6m/s穿过右拱洞的8s轨迹，直接在每次atomicAdd检测溢出，逐帧累计检测到的溢出为0，见 `overflow-stress.json`。同一物理时刻重复渲染的PNG逐像素一致，哈希见 `hot-repeat/same-time.json`。

所有性能测试均关闭录像、一次只有一个测试实例，GPU完成后计帧；另一个可访问的项目页面已暂停。没有关闭用户无关应用。系统并非可证明的独占GPU环境：不运行测试时，ioreg仍返回96–99%的设备利用率读数；该系统读数不能归因到单个进程。前两组旧版也只有约26–29fps，**失败数据完整保留**在 `performance/`、`performance-repeat/`，不能用后面的结果抹掉它们。
