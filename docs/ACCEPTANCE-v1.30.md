# v1.30：让看得见的水波也主导池底聚光

本轮将主导聚光的波段改为水面上能读出的尺度，并减弱另一套背景起伏。没有增加焦散层，也没有修改照明、材质、光子预算或重建滤波。代价是放弃上一轮非常细小的纹路，换成能辨认来源的较宽光带与聚光点。

## 原因与实施

原模型在物理上已经共享水面，但视觉上由两套不同波段主导。旧背景高度标准差8.775mm、斜率RMS 0.06294；6–18cm波段高度仅0.156mm、斜率0.01031，却有0.788m⁻¹的拉普拉斯曲率RMS，与背景0.782m⁻¹相当。因此肉眼看到的是背景起伏，聚光中却多出另一套几乎看不见的细结构。单纯继续提高池底接收分辨率不会消除这种错位。

保留16个分层方向、随机相位及3倍波长跨度，将波长从6–18cm改为24–72cm，合成模态幅度参数从0.22mm改为6mm（每方向1.5mm，统计高度约4.25mm）。有限水深色散的时间系数从0.03改为0.12，仍乘场景waveSpeed=0.28。它确实推进水面几何，而不是移动一张光纹。

新增`ambientWaveStrength=0.1`，仅降低背景初始位移和背景驱动；身体色散尾迹仍用原配置，显式脚步压力不缩小。解析波、背景波和身体波继续经共享`wave()`用于相机光线、太阳折射和天光传输。没有单独为池底设置另一份波形。

## 可比数据及其含义

所有数值在t=6秒、同一池底区域测量。照度CV来自x=2.5–4.5m、z=−2–0m的2m方形GPU太阳照度读回。水高与光照对应关系在以平水折射位移回推的1.6m水面区域采样400²点，使用实际法线追到池底后读取GPU照度。裁去数值微分边界和越界点，保留97.0225%；该状态没有因强聚焦折叠而额外丢点。

| 量 | 修改前 | 最终 |
|---|---:|---:|
| 总水高标准差 | 8.776mm | 4.282mm |
| 背景 / 解析波斜率RMS | 0.06294 / 0.01031 | 0.00644 / 0.07010 |
| 背景 / 解析波曲率RMS（m⁻¹） | 0.782 / 0.788 | 0.0795 / 1.366 |
| 水高与其折射落点照度的Pearson相关性 | 0.4106 | 0.7872 |
| 光束面积压缩预测与GPU照度相关性 | 0.9976 | 0.9999 |
| 2m区域太阳照度CV | 0.2398 | 0.2931 |

水高相关性是辅助的形态指标，不是通用物理定律，也不能替代观感。聚光由曲率、入射方向和传播距离共同决定，波峰与光斑不是严格一一复制。接近1的光学预测相关性在旧版就存在，不能冒充本次视觉改善；它只证明光确实由共享水面折射产生。CPU核验用中央太阳光线，GPU仍含太阳盘采样，所以不宣称逐数值完全相等。

试过只增大原背景波：高度13.01mm，形态相关性仍只有0.400，未采用。保留35%背景的方案相关性0.684；进一步降到10%后达到0.787，因此采用后者。最终主波同时占据可见斜率和聚光曲率，不再让两套波各自争夺一种观感。

## 性能与验证

最终生产代码在1280×832固定内部像素下，7个明区／暗区静止、慢走、快走及池底俯视场景，均值范围32.80–35.08fps，最低完整一秒32.50fps，首帧532.7ms。每例预热2.5秒、运行6秒；所有场景无GPU错误，没有超过50ms的帧。详见[performance.json](../../workroom-v1.30-evidence/performance-final/performance.json)。

测量时只有一个本任务测试浏览器；截图、录像编码已结束，没有并行测试。空闲GPU计数仍记录到FlopsDesktop的Electron、WindowServer、UURemote和少量WebKit活动，没有关闭用户应用，因此不声称独占GPU。即使在这份实际桌面负载下也通过30fps。初次完整运行也通过，但中途修改了源码注释，可能触发Vite热更新，所以交付使用停止编辑后重新执行的`performance-final`，不采用初次值背书。

## 边界

本轮没有保留毫米级细丝目标，光带更宽。局部同刻与12秒序列说明对应关系明显改善，不声称每个视角、每个波峰都能无歧义地认出唯一光点，也不把一次相关系数当作人的最终验收。焦散的真正对应是水面曲率经折射投到池底，不能靠复制水面亮纹达成。
