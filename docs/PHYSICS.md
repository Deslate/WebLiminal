# v1 光传输：可以审计的部分

这版移除了 Three.js raster renderer、Reflector、水光发光纹样和首帧 JPEG。运行时不读取任何图像资源。四个 WebGPU pass 依次执行光子传播、世界表面密度估计、相机路径和镜头呈现。

## 光从哪里来

唯一室外入口是有厚度的矩形天窗。太阳有 0.00465 rad 角半径，天空是程序化的方向辐亮度函数。天窗缩小时，遮挡几何、发射面积、发射位置和每条路径的功率都会一起改变，不是给画面乘一个亮度系数。

太阳发射包的功率为 `E_sun × apertureArea × abs(direction.y) / probabilityOfChoosingSun`；天空使用余弦半球采样，其功率为 `L_sky(direction) × π × apertureArea / probabilityOfChoosingSky`。交互默认及本次终稿每批发射 65,536 条路径；每张终稿累积 1,024 批，共 67,108,864 条发射路径。这里还没除以路径数量，数量归一化发生在密度估计时。

## 水是相交几何

`common.wgsl::wave()` 返回水面的高度和两个解析偏导。8 个不同方向/波长的重力波叠加 3 个毫米级毛细波；频率不构成一张平铺贴图。`traceWater()` 在波面包围高度内进行数值求交，接受残差小于 2 mm 的命中。相机和光子共享这个函数。

命中介质界面后计算空气/水折射率 1.0 / 1.333 的非偏振菲涅耳反射率 F，以及斯涅尔折射方向。为减少微弱反射焦散的噪声，反射分支被过采样，其通量仍乘 `F / p`；折射分支乘 `(1-F)/(1-p)`。没有给反射焦散额外加亮。光子携带通量，相机携带辐亮度，只有相机折射使用 `eta_i² / eta_t²`。水中每段路径都用 Beer–Lambert `exp(-sigma_a * distance)` 衰减 RGB，其中吸收系数为 `(0.34, 0.075, 0.037) m⁻¹`。

介电界面的参考定义：[PBRT Dielectric BSDF](https://pbr-book.org/4ed/Reflection_Models/Dielectric_BSDF)。

## 墙上的图案如何出现

光子离开波面后，继续与房间的解析平面、盒体及拱洞圆柱面求交。在实际接收面上，以双线性 splat 累积 RGB 通量。每个表面有独立的米制坐标格，拱洞内部与外部使用不同的格，避免两侧串光。接收位置不是屏幕坐标。

`resolve.wgsl` 对接收格使用归一化的 3×3 tent 密度核：

`irradiance = weightedSum(photonFlux) / (kernelWeight × emittedPhotonCount × physicalCellArea)`

这些 storage buffers 是运行时由光子命中写出的世界空间照度估计，不是贴在墙上的图案资源。改变水位会改变入水点、界面法线、折射后的水中距离和出水/反射后的接收位置；改变天窗会改变哪些路径有机会进入室内以及总通量。局部路径聚集导致亮斑，稀疏区域变暗。

第一处直接漫反射命中不计入光子图，由相机的 next-event estimation 负责；经过水界面的焦散以及之后的间接传输计入光子图。光子继续以材质 BSDF 采样反弹，最多 7 次，使用俄罗斯轮盘。相机追踪最多 6 次水界面/釉面反射，漫反射项读取光子估计，直射光用阴影射线求可见性。方法依据：[PBRT Photon Mapping](https://www.pbr-book.org/3ed-2018/Light_Transport_III_Bidirectional_Methods/Stochastic_Progressive_Photon_Mapping)。本实现是固定核宽的表面光子密度估计，不是 PBRT 的完整 SPPM 实现。

## 材质与相机

`materials/porcelain.wgsl` 独立生成每片瓷砖色差、釉面 GGX 粗糙度、灰浆接缝、边缘法线、缺损、少量裂纹、污渍和平均水位线。天空不来自 HDRI，雾使用均匀介质消光及带阴影测试的单次太阳散射。镜头是 36×24 mm 感光面裁切、28 mm 焦距、f/5.6 圆形薄透镜采样，焦点 10 m；色调映射为解析 ACES 拟合，色散、暗角和颗粒也由程序计算。

## 实际的误差与取舍

- 这是有偏的有限密度核估计。常用接收格约 2–2.5 cm，其他面较粗；有限核会柔化极细的焦散，不是无限采样的解析解。
- 光子 RGB 通量用 1/2048 的定点原子累积，存在小的量化误差。有限路径长度省掉了很长的间接路径。
- 水面来自确定性的波形模型，不是 Navier–Stokes 流体；求交也是有容差的数值求解，掠射角存在有限迭代误差。
- 瓷砖接缝、橘皮和缺角主要是程序化 BRDF/法线层，未将每一条接缝凹槽都细分为几何。釉层使用能量衰减的 Lambert + GGX 模型，没有完整的釉下多次散射。
- 空气只算单次太阳散射；不包含完整体积多次散射。RGB 模型不等于光谱渲染。
- 为避免把不断移动的波面平均成假照明，普通运行在相机静止后固定模拟时刻，让同一场景逐渐收敛。移动时恢复动态波面和短时域历史。这是明确的交互取舍，不宣称一直实时解算流体。

## 防伪验证

`npm run proof` 使用同一个页面、同一个 WebGPU device、同一个运行 UUID。三张主图仅改变水位或天窗宽度，机位、焦距、曝光、随机种子、波相位、波高和采样次数保持不变。

GPU 另外回传实际路径的入射方向、波面命中、法线、介质 IOR、选中的分支、出射方向、命中接收面以及分支前后通量。`scripts/optical-audit.mjs` 用独立 JavaScript 公式复算高度、法线、Fresnel、反射/折射定律和重要性权重；它不读取一张用于“证明”的预画图案。最终还恢复原参数重渲染，要求 PNG 的 SHA-256 与初始图完全一致。
