## 为什么确定是它

瓷砖边长250mm，池底接收格20.833mm；规则细网的主要x方向周期为57.14mm（17.5cycles/m）。当前天光在14×27m水面上用256×512点采样，源间距54.69×52.73mm。通过0.42m水深的近轴折射投影，预计约57.72×55.66mm，与实测吻合。

进一步将源网格改为128×256、其余不变，主要周期变成117.65mm（8.5cycles/m；2m窗口频率分辨率为0.5cycles/m）。接收格和瓷砖都未变化。这是源采样印记的直接干预证据，不能用材质或接收格解释。

逐项A/B的结果如下，原始图和读回分别在同名目录：

| 对照 | 结果 |
|---|---|
| `no-cache`：关闭缓存间接光 | 细网仍在，动态照度中的网格频带功率完全不变 |
| `no-bounce`：关闭动态漫反射传播 | 细网仍在 |
| `no-sun`：关闭太阳分支 | 暗部细网仍在，动态照度完全不变 |
| `no-sky`：关闭折射天光 | 暗部动态照度归零，细网消失；缓存间接光仍在 |
| `wide-cache`：只恢复v1.29缓存滤波 | 缓存斑驳减弱，细网仍在 |
| `sky-half`：天光源间距加倍 | 细网主要周期约翻倍 |

这里的细网不是严格逐像素静止。固定的是规则采样骨架；水波使落点和亮度略变。t=6→66秒，原版动态照度的相对RMS变化13.17%，但细网持续可辨。真正的缓存光子在这60秒内逐位不变。以前将两者混为同一静态底纹，遗漏了动态天光重建本身的采样印记。

## 修复方式及数字

每个天光包的功率本来就代表一个有限水面单元，却只被双线性分配到池底2×2单元，随后使用很窄的重建核。源点间距约55mm，接收格只有21mm，规则包中心之间的能量起伏因此被保留下来。

现在天光包仍按实际水面法线执行Fresnel/Snell、遮挡和吸收，但在池底接收时，以它代表的水面单元投影宽度作归一化三角核分配。投影零点半宽约57.7mm，约2.77个池底格；默认覆盖最多6×6格。权重逐包归一化后再进入原有整数通量累加、接收面积归一化与光照系统。没有额外渲染层、贴图案、帧间随机抖动、历史图像混合或全画面模糊。

只有天光到池底使用这个有限面积重建，太阳包及墙面继续走原有分支；太阳焦散没有被同样展宽。波形、天光能量公式、光子数量和缓存间接光未改。

| 动态照度平均值（GPU线性单位） | 0.155297 | 0.154239 |

指定网格频带功率降低**99.997%**，平均照度只变化**−0.6815%**，并非靠提亮掩盖。剩余动态照度仍随水演化。`fine0`缓存读回（保存的9×6m区域）在改前/改后逐位相同，证明没有通过抹掉缓存光或替换材质取得结果。

频带指标：2m窗口、96²原始接收格；减去σ=4格的Gaussian低频分量，除以ROI均值，施加二维Hann窗后FFT。统计轴向16–20cycles/m、正交方向绝对频率<1.5cycles/m的功率。99.997%只指这个已定位的规则网格频带，不是宣称所有误差降低同样比例。小尺度RMS使用上述去低频残差，未施加Hann窗。

生产代码、固定1280×832、Chrome headless，明区/暗区各静止/慢走/快走六例：均值**60.05–61.43fps**，最低完整一秒**59.93fps**，最差p95 **18.0ms**，首帧594.3ms；无超过50ms帧，无GPU错误。太阳147456包/帧、天光524288包/帧及四轮间接传播未降低。测试独立运行，没有本任务并行录像、截图或GPU实例；未关闭用户其它应用，不声称GPU独占。

`npm test`16/16、构建与零位图校验通过。六种机位的连续变化、相机历史独立性、光学路径同步与30/60Hz停步细化检查通过。池底回归通过：观测窗口聚光峰值为平水2.244倍，开口面积缩为1/4后的通量比0.2544，深水吸收与相机独立性检查通过；结果见`floor/capture.json`、`floor.log`。自动证据断言要求指定网格频带至少降低95%、平均照度变化小于2%、缓存照度逐位不变；实际均通过。

## 没做到的部分

足迹宽度采用平均水位的近轴投影近似，未计算随曲率完全变形的光束Jacobian；天光小于约一个源间距的细节仍未充分解析。原v1.16缓存间接光的低频斑驳仍保留，本轮未把它冒充动态焦散或全部删除。此次修复的是已复现的规则天光细网，不声称消除了所有光照近似、覆盖所有机位或保证任意设备30fps。
